# App Audit Report — 2026-04-25

## Scope
- Static inspection of Gradle/build configuration and repository hygiene.
- Attempted to run unit tests.

## Commands executed
1. `./gradlew test --no-daemon`
2. `java -version`
3. `rg -n "@Entity|@Dao|@Database|RoomDatabase|androidx.room" app/src/main/java app/src/test/java`
4. `git ls-files | rg -n "(\\.orig$|/release/.*\\.aab$|\\.jpg$|how .+jules)"`

## Findings

### 1) Build/test blocked by strict Java 21 toolchain requirement
- The module explicitly requires Java 21 in three places: `sourceCompatibility`, `targetCompatibility`, and `jvmToolchain(21)`.
- In this environment, only Java 25 was detected (`openjdk version "25.0.1"`), and Gradle failed to resolve a Java 21 toolchain for `:app:testFullDebugUnitTest`.
- Impact: local/CI test execution fails unless JDK 21 is installed or toolchain auto-download repositories are configured.

### 2) Potential dependency misconfiguration: Room compiler in runtime classpath
- `implementation(libs.androidx.room.compiler)` is declared in app dependencies.
- No Room usage (`@Entity`, `@Dao`, `@Database`, `RoomDatabase`) was found in `app/src/main/java` or `app/src/test/java`.
- Impact: unnecessary dependency bloat and possible confusion. If Room is intended, compiler should be configured via KSP/KAPT and runtime via `room-runtime`.

### 3) Lint is globally disabled for all tasks
- A `tasks.configureEach` block disables every task whose name contains `lint`.
- Impact: static checks are silently skipped, increasing risk of shipping regressions and policy issues.

### 4) Repository hygiene inconsistencies
Tracked files that look like accidental or generated artifacts:
- `app/src/main/java/com/example/swadebuilder/ui/sections/PericiasSection.kt.orig`
- `app/lite/release/app-lite-release.aab`
- `lite/release/app-lite-release.aab`
- `Screenshot_20260203_122122_Adobe Acrobat.jpg`
- `how hash_do_commit_do_jules`

Impact: inflated repository size, noisy history, and higher chance of stale build outputs being confused with source of truth.

## Recommended next actions
1. Decide if the project should strictly require JDK 21. If yes, document/install it in CI and contributor setup; otherwise relax the toolchain strategy.
2. Remove or migrate `room-compiler` dependency according to actual persistence approach.
3. Re-enable lint (at least in CI/release pipelines).
4. Remove generated/artifact files from version control and add ignore rules where appropriate.
